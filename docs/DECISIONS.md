# DECISIONS — принятые решения

Формат: что решили → почему.

## Этап 1
- Three.js 0.170 + Vite + TypeScript; `/assets` раздаётся плагином `serve-assets` (dev — middleware, build — копирование в `dist/assets`). Папка `public/` не используется.
- Рецепт картинки взят 1:1 из `tools/style_test/index.html` (ACES, лунный DirectionalLight, hemi, FogExp2 0.034, HDRI night_512, bloom 0.75/0.7/0.82, грейд, виньетка, зерно). Сравнение со скриншотом `proof_night_street_a.png` — визуально идентично (`docs/screenshots/progress_stage1_a.png`).
- Статика расставляется через `StaticBatcher` (InstancedMesh на модель+часть) ради лимита ≤400 draw calls; всё интерактивное/прозрачнеющее — обычные объекты.
- Пул из 12 PointLight, переназначаемый на ближайшие фонари (спека §4.2).

## Симуляция (src/sim, чистый TS)
- **Время:** тик 0.5 игр. с, окно 2400 с (21:20→22:00). Состояние мира — JSON-совместимый объект (клонируется `structuredClone`, хэшируется `hashState`).
- **ГСЧ:** без `Math.random`/`Date.now`; `hrand(seed, ...keys)` — безсостояний хэш→[0,1) (подсистемы не связаны потоком), `Stream` — сидированный xoshiro128**. В мире рандом нужен только для малых сдвигов расписания (±6 с).
- **Граф вместо сетки 0.5 м:** маршруты NPC — Dijkstra по графу из ~70 узлов (`map.ts`), рёбра блокируются динамически (бочки Бориса). Это упрощение A* на сетке (см. DEVIATIONS).
- **Причинность:** `emit(type, actors, causeKeys)` — причины берутся из «хвостов» сущностей (`tail[actor]`): последнее событие, затронувшее NPC/предмет/вентиль. Цепочка «проездной → пожар» получается из того, кто что трогал, а не из прописанной связи; тест `sim:cascade` ищет путь PICKUP→…→IGNITION по графу причин и grep'ом проверяет, что в `src/sim` нет связок «проездной → пожар».
- **Давление:** `dP/dt = (1+1.6v − P)·v/τ − w·B`, где v — вентиль подачи, w — стравливание (B = 0.05 бар/мин, как в спеке). τ = 220 с. При v=0 сеть «держит» давление (газгольдер), поэтому стравливание реально опускает P (спека хочет ≈0.3 к 21:50). Утечка стыка кухни `q = k·(P−2.0)^4`, газ — три клетки (плита/кухня/зал) с диффузией и вентиляцией (вытяжка, окно, дверь); воспламенение при ≥5 % и источнике огня в клетке.
- **Подгонка цифр** (инварианты важнее): baseline → поджог ≈21:58:40 (на всех сидах 1…12), «проездной у Тильды» → газ к T1 ≈2.5 % (без пожара), стравливание в А → ≈3.5 % (без пожара).
- **Диалоги — часть симуляции:** выбор реплики = вмешательство `say` (детерминированная проверка `навык+бонусы ≥ сложность`, без костей). Время: реплика 6 с, выбор 15 с, проверка +10 с — списывает `Session`.
- **Предметы-двойники:** прыжок несёт предмет из рук. Если оригинал есть в мире, у игрока «мерцающий» двойник: его нельзя отдать NPC и нести дальше. Оригинал исчезает в момент `origVanishT` (когда игрок забрал его в прошлой ветке). Монеты/билет/кружка — «взаимозаменяемые», двойник сразу настоящий, но оригинал всё равно исчезает.

## Правила Окна (чтобы кратчайшее решение требовало ≥3 прыжков)
1. Окно **запечатано** до «урока ключа»: первый прыжок обязан нести вентильный ключ (спека §13).
2. Окно работает, пока башня открыта: 21:20–21:52 (в 21:52 Клара закрывает башню на церемонию).
3. «Нить» (возврат после T1, когда башня уже закрыта) несёт только знания, **не предмет**.
4. Прыжок вперёд (взгляд в T1) считается прыжком; после него ветка заканчивается, остаётся только возврат.
5. Знания, которые нельзя получить раньше: K1 (пожар) — только в T1; K2 (стык течёт) — только при утечке, т.е. после ~21:55, когда Окно уже закрыто.
6. Ключ доступен лишь с 21:36 (повесили на крюк), монеты Пип — лишь с 21:34, а решения требуют предмет в начале ветки (стравливание — до 21:36; билет Тильде — до 21:27).
Итог поиска (`sim:solve`): для «информированного» игрока (знает K1…) минимум **3 прыжка** у всех трёх классов A/B/C; без гейта знаний (физически) B достижим за 2 — это отражено в отчёте отдельной строкой, ничего не скрывается.
