# 03 · Стартовый промпт для облачной сессии (вставь целиком)

```
Ты — старший инженер-геймдев (TypeScript/Three.js/Vite). Работаешь в репо `okno`, в ветке `v2/chasovaya-nabereznaya`
(она уже создана и содержит распакованный пак: /assets, /docs, /tools, CREDITS.md и старый код в /reference_old).

ЦЕЛЬ
Собрать мини-уровень «Часовая набережная» игры «Окно» — красивый, живой, с рабочей симуляцией и каскадом «проездной».
Единственный источник правды: docs/01_LEVEL_SPEC.md. Гайд по ассетам: docs/02_ASSET_GUIDE.md.
Референс картинки: docs/screenshots/proof_*.png и tools/style_test/*.html (проверенный рецепт света/пост-обработки).

СТАРЫЙ КОД
В папке `reference_old/` лежит старая версия игры. Она была сделана под другую игру (киберпанк, убийство) и под другой мир,
поэтому сильно отличается от нового проекта по устройству и по контенту, а по качеству заметно хуже:
некрасивая картинка, бездушные NPC, мало диалогов, простая симуляция. Новый проект пишется С НУЛЯ в `src/` по спеке.

Что можно оттуда взять (только прочитать и понять логику, потом переписать у себя под новую спеку):
- как считается детерминированный хэш состояния и как устроен сидированный генератор;
- формат хранения диалогов и проверок навыков;
- как устроена локализация Ru/En;
- идея журнала знаний и тестов на детерминизм.

Чего НЕ делать:
- не импортировать файлы из `reference_old/`, не копировать целыми модулями;
- не наследовать его структуру папок, модель мира, сущности и сценарий;
- не чинить и не улучшать старый код.

Это небольшая часть работы: максимум 10 минут чтения, дальше только новая спека. Когда уровень готов, папку `reference_old/` удалить.

ЛИМИТ
У пользователя базовый 5-часовой лимит на всю работу. Не гоняй лишние проверки и скриншоты, кроме двух обязательных (после этапов 1 и 4).
Приоритет: этапы 1–4 и минимальная симуляция (трамвай, газ, огонь, каскад) важнее объёма диалогов. Диалоги — по 5–8 реплик на NPC.
Коммить и пушь после каждого этапа, чтобы работа не пропала при остановке по лимиту.

ЖЁСТКИЕ ПРАВИЛА
1. Детерминизм: src/sim — чистый TS, без THREE, без Math.random/Date.now; seed + вмешательства → один хэш.
2. Никакого LLM в игре. Ru/En локализация, все строки — ключи.
3. Каскад «проездной → пожар» НЕ скриптовать: только общие правила (спека §8, §10). Тест `sim:cascade` обязателен.
4. Солвер `sim:solve` должен подтверждать: ≥3 прыжка нужно кратчайшему решению, ≥2 класса решений.
5. Всё интерактивное по таблицам спеки §5; бесшовный вход в здания; трамвай реально ездит и проверяет проездной.
6. Ассеты — только из /assets (CC0). Если чего-то нет — собери кодом из кусков пака, а не качай. Сеть наружу, кроме GitHub и npm, закрыта.
7. Не раздувай: это ТЕСТОВЫЙ срез на «ВАУ». Если пункт спеки нереален — упрости и запиши в docs/DEVIATIONS.md, но НЕ молча.

ПОРЯДОК (коммить после каждого этапа, пуш в ветку)
Этап 1 каркас + картинка (сравни скриншоты) → 2 мир → 3 NPC → 4 интерьеры → 5 симуляция → 6 диалоги/журнал/«Вестник» → 7 тесты → 8 полировка.
После этапа 1 и после этапа 4 сделай скриншоты (Playwright + chrome с флагами SwiftShader: --use-gl=angle --use-angle=swiftshader
--enable-unsafe-swiftshader --ignore-gpu-blocklist --no-sandbox) и положи в docs/screenshots/progress_*.png.

РАБОТАЙ АВТОНОМНО
Не задавай вопросов, принимай разумные решения сам, фиксируй их в docs/DECISIONS.md. Если застрял на одном элементе >20 минут — упрости и иди дальше.

ПРИЁМКА (все галочки раздела 16 спеки). В конце: коротко опиши, что работает, что упрощено, как запустить (npm i && npm run dev) и как прогнать тесты.
```

## Подсказки для тебя (не для модели)
- Если сессия слишком дорогая — сузь до этапов 1–4 + минимальной симуляции (трамвай, газ, огонь), диалоги — по 5–8 реплик на NPC.
- Первая проверка качества — скриншоты этапа 1. Если не «ВАУ», останови и поправь свет/масштабы до продолжения.
